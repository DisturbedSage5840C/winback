# winback-dashboard

React 19 + Vite + Tailwind CSS v4 + TypeScript. The read-only front end for Winback;
every number it shows is fetched from the FastAPI service in `../api`, and nothing in
here is mocked. If a value cannot be fetched, the component says so rather than
substituting a plausible one.

Scaffolded from a Figma Make export and then rewritten. The `.figma/make/` scripts and
`site.json` are still load-bearing — `vite.config.ts` imports `site.json` for the
document shell and mounts four Figma Vite plugins — so do not delete that directory.

## Development server

Vite serves on `$PORT` (default 8443). `../scripts/run_demo.sh` starts it alongside the
API on `:8000`; `npm run dev` starts it alone, which is only useful against an API that
is already up.

Install with **`npm install`** — that is the tested path. `pnpm-lock.yaml` is committed
and `.mise.toml` pins pnpm 10.34.3, but pnpm is not installed on the build machine and
that route is unverified.

## Project structure

Canonical. Start with the task-relevant files; follow imports only when this guide is
missing a path or the repository contradicts it.

- `src/main.tsx` — entrypoint; imports `src/index.css`, mounts `src/App.tsx` on `#root`
- `src/App.tsx` — `HashRouter` and the chrome. **Not** where feature work goes; it
  routes to `src/pages/`. HashRouter rather than BrowserRouter because the demo is
  served from a static build with no server-side rewrite
- `src/pages/` — one file per route: `Overview`, `Worklist`, `Invoice` (the drill-down),
  `Compliance`, `Evaluation`
- `src/components/` — `Funnel`, `LiveTrace`, `CompliancePanel`, `WindowStrip`,
  `WorklistTable`, `RunSelector`, and `ui.tsx` (the shared primitives: `Panel`,
  `SectionHeader`, `StatusChip`, `VerdictChip`, `RootCauseChip`, `AttemptsBar`,
  `Spinner`, `ErrorState`, `EmptyState`, and the `statusColor` / `verdictColor` maps
  that keep the semantic palette in one place). New shared UI belongs in `ui.tsx`
- `src/lib/` — `api.ts` (every fetch, one place; `API_BASE` defaults to
  `http://localhost:8000` and is overridden by `VITE_API_BASE`), `types.ts` (the API
  contract, kept in step with `../api/main.py`), `hooks.ts` (`useAsync`,
  `usePageVisible`, `usePrefersReducedMotion`, `useCountUp`), `format.ts` (`rupees`,
  `pct`, `mmss` and friends — never format money inline)
- `src/index.css` — Tailwind v4 import, the palette tokens, and `@font-face`
- `vite.config.ts` — React, Tailwind v4, the `@` → `src` alias, and the Figma plugins
- `public/docs/assets/*.png` — figures generated by `python -m eval.report`; regenerate
  them there, never edit them here

The API contract lives in `../docs/FRONTEND_SPEC.md`. If a response shape surprises you,
that document and `../api/main.py` are the authority — not this file.

## Styling and motion

Tailwind CSS v4 via `@tailwindcss/vite`; `src/index.css` does `@import 'tailwindcss'`.
No `tailwind.config.js` and no PostCSS config, by design. Theme customisation and global
CSS go in `src/index.css`.

Colour is semantic and fixed: blue = agent action, green = recovered, red = blocked by
the guardrail, amber = escalated, slate = written off. Do not reuse a status colour for
a series.

The motion budget is four animations — the recovered count-up, the funnel stagger, the
live-trace row flash, and the drill-down drawer — specified in
`../docs/FRONTEND_SPEC.md`. Framer Motion is here for those four. Adding a fifth is a
decision to make in that document first. `prefers-reduced-motion` is respected
throughout and must stay that way.
